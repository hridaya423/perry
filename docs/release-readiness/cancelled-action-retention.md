# Cancelled action retention

Owner: PerryGuide. Scope: M3 automatic cancellation completion in ResumableTaskRunner and TaskCoordinator. This is package-level evidence from the development checkout, not live Cua or clean-checkout release proof.

The regression entered an effectful action through approval and the durable beginStep boundary, cancelled the run, and waited for the fixture to acknowledge CancellationError. Previously, automatic completion removed the task despite its in-flight action marker. The live coordinator and a reloaded coordinator both lost the record: one test failed four assertions in /tmp/perry-cancelled-checkpoint-before.log on August 31, 2026.

TaskCoordinator.finishCancellation now requires persisted cancellation intent. It retains a reconciliation-required record in paused state without clearing its checkpoint, cancellation intent, or recovery disposition. Repeated completion leaves that record unchanged. When no reconciliation is required, cancellation can finish and remove the record as before. ResumableTaskRunner uses this operation for its blocked, cancelled outcome; explicit discard remains separate.

The regression now checks retention before and after reload, rejection of resume without executing another action, duplicate completion, preservation of an unrelated queued task, and explicit discard. A second test checks that completion requires cancellation intent and can remove an undispatched task. All 109 PerryGuide tests passed in /tmp/perry-cancelled-checkpoint-guide.log on August 31, 2026. Independent source review found no new blocking issue in the coordinator method, runner call, or cancellation fixture; the reviewer did not run tests or builds.

The app's non-running cancellation path now calls finishCancellation and uses the shared outcome handler. When a launch wrapper exists but cancellation precedes runner startup, the handler resolves its nil outcome against the persisted cancellation intent. It retains uncertain records instead of leaving the task waiting to retry. Independent source review found no blocker in these paths. The unsigned Apple Silicon Debug app suite passed 248 tests with two live Cua skips in /tmp/perry-worker-retirement-final-app.log; that run does not prove the cancellation UI journey.

A Cua worker has not been terminated by this retention change, and no external effect is claimed to have been undone. Process isolation, bounded worker exit, resource release after exit, UI-path verification, and live relaunch recovery remain open release gates.

System stop differs from explicit user cancellation. The additional test `testSystemStopRetainsPausedIntentAndUncertainActionAcrossReload` persists pause intent before cancelling the running task. Reload retains that intent, the in-flight action, and the reconciliation requirement, without setting user cancellation. An unrelated queued record remains unchanged, and resume dispatches no replacement action. All 110 PerryGuide tests passed on August 31, 2026, at 15:19:50 in `/tmp/perry-system-stop-guide-full.log`. This characterizes the existing package behavior; the app shutdown migration still needs integrated verification.
