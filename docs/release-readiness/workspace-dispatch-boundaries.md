Owner: Perry execution runtime. Scope: WorkspaceFileRuntime on the current dirty Apple Silicon development checkout. This record does not establish clean-checkout reproduction, complete filesystem confinement, or a release-proven execution capability.

On August 31, 2026, a create-file regression reproduced replacement of an existing dangling symbolic link. The runtime's previous existence check followed the link, treated its missing destination as a new file, and replaced the link during the atomic write. `/tmp/perry-workspace-symlink-red.log` records the failed rejection and failed link-preservation assertions. The runtime now inspects each relative path component, rejects symbolic links even when their destinations are missing, and propagates inspection errors other than a missing path. This proves rejection before dispatch; it does not prove interruption of a filesystem operation already in progress.

The tests use temporary directories and controlled tasks. They do not close the production Cua ownership migration, authenticated runtime smoke tests, live cancellation latency, or the filesystem check/use race under concurrent external mutation. Those remain separate release requirements.

The parser distinguishes file creation from directory creation and accepts only an absent directory flag or the explicit strings `true` and `false`.

The regression in `/tmp/perry-workspace-typed-red.log` reproduced four invalid directory flags creating regular files. Its read-back fixture also checks the original action ID and leading whitespace in file contents.

This is an executor-boundary migration, not the complete M1 plan model. Planner output, persisted plans, and the app's workspace verifier still use legacy payloads. Independent source review found no P0/P1 in the parser, filesystem behavior, or boundary shape; the reviewer did not rerun tests. No feature status is promoted.

## Creation verification

The production filesystem verifier now requires a matching successful action receipt. For creation, it checks the requested item type and compares regular-file contents with the requested UTF-8 bytes. An invalid directory flag or a read-back error produces an unverified result.

The regression run at 16:41:18 on August 31, 2026, verified changed contents and accepted a failed receipt before the fix; both tests failed in `/tmp/perry-file-verification-red.log`. After the fix, the runtime package passed 153 tests, with ten live-provider tests skipped and zero failures, at 16:42:06 in `/tmp/perry-file-verification-green.log`. The fixtures also check a regular file requested as a folder and a receipt belonging to another action. Independent review is pending.

This verifies observed creation state, not exclusive ownership of the filesystem between checks. Rename and trash verification still use their existing path-existence checks; the change does not establish content identity for those operations or remove the concurrent path-replacement limitation.

The verifier now resolves its workspace root and rejects targets that resolve to a different path, as well as the root itself. The fixtures cover successful directory creation and both file/directory type mismatches.

## Self-describing execution receipts

New workspace execution receipts persist a typed effect rather than collapsing every operation into a path and byte count. File creation records the path and exact byte count, directory creation records its path, rename records both paths plus the approved device and inode, and trash records the source identity plus the generated Trash entry name. Journal recovery validates the receipt against the typed action and its postcondition. The decoder retains the old path-and-byte-count representation only as an explicit legacy case so existing journals remain recoverable during migration; it rejects records that mix both representations or add unknown payload fields.

The complete Runtime suite passed 229 tests with ten credential-dependent provider tests skipped in `/tmp/perry-typed-receipt-runtime-final.log`. The complete Guide suite passed 184 tests with no skips or failures in `/tmp/perry-typed-receipt-guide-final.log`; its eleven workspace-execution-journal tests all passed. The strict decoder now rejects malformed legacy effects at the receipt boundary, including an empty path with a negative byte count; `/tmp/perry-legacy-receipt-red.log` and `/tmp/perry-legacy-receipt-green.log` retain the red and green runs. The app suite passed 323 tests with two permission-gated live-Cua tests skipped. Its result bundle is `Test-Perry-2026.08.31_23-30-04-+0100.xcresult`, and the build output is `/tmp/perry-typed-receipt-app-final.log`. The final unsigned Apple Silicon Release build passed in `/tmp/perry-typed-receipt-release-final.log`.

These results prove typed persistence, strict decoding, recovery compatibility, and Release compilation on the current dirty checkout. They do not prove a live user Trash operation, process death between dispatch and receipt persistence, signing, notarization, or clean-checkout reproduction. The capability remains `unit-tested`.
