# Selected planning contract

Use the result candidate with an explicit legacy interface and one selected provider throughout context acquisition. The independent comparison scored the result candidate 21/25 and the capability candidate 19/25. The parent read both completed candidates and agrees with the choice because the result boundary moves validation into the provider instead of adding a second selector path. These scores compare designs, not release readiness. Both candidates and the judge used the user-requested Luna family; no candidate dropped out.

## Interfaces and migration

Rename the existing planning protocol to `LegacyTaskPlanner`; preserve its `plan(goal:context:) -> Plan` contract. The existing `AgentRuntime` aggregate continues to inherit that legacy protocol and `ActionExecutor` during migration. Do not introduce another broad runtime aggregate or rename every existing executor merely to add the new planning boundary.

The canonical `TaskPlanner` has `id`, `capabilities`, and `plan(_ request: PlanningRequest) async throws -> PlanningResult`. `PlanningRequest` carries the real goal, task ID, normalized absolute file workspace, and `PlanningContext.none` or `.screen(ScreenContext)`. Construction rejects empty goals and invalid workspace URLs. `PlanningResult` distinguishes `.typed(ExecutionPlan)` from `.legacy(Plan)`. `PlanningError.contextRequired` is the only reason to acquire desktop context; malformed input and typed-plan rejection stop the attempt.

`LegacyTaskPlannerAdapter` is one-way. It wraps a real legacy planner, requires supplied screen context, invokes the old method, and returns `.legacy`. It never creates a request identity or workspace and never converts typed actions into legacy steps.

`RuntimeProvider` owns a canonical planner, an optional legacy planner, and its optional executor. Existing legacy initializers wrap their planner automatically; a canonical initializer accepts `planner`, optional `legacyPlanner`, optional `executor`, and `descriptor`. The local provider registers the same value through both interfaces explicitly. A typed-only provider has no legacy runtime view; `adaptedRuntime` and the route's compatibility runtime become optional rather than manufacturing an unsupported legacy adapter. Existing foreground and recovered legacy callers must reject a missing compatibility view explicitly.

`ProductionRuntimeSelection` retains the selected provider and its explanation. Identity, display name, and the optional legacy runtime are projections of that provider. New queue planning calls `selection.provider.plan(request)`. Descriptor and latency updates preserve both planning interfaces.

## Validation and context

`RuntimeProvider.plan` enforces declared planning support, cancellation before and after the planner, and result binding. A typed result must match the requested task ID and goal. Workspace-bearing operations must match the exact normalized workspace bytes required by the executor, not merely fall under a descendant path. Existing plan constructors remain responsible for canonical action and scope validity. A legacy result requires supplied context and retains the selected provider identity, as the existing adapter does.

The queue selects once with the existing eligibility and preference rules. It first plans with no screen context. On `contextRequired`, it probes permissions and captures one exact Cua target, then retries the same provider once with that context. A repeated context request fails; no independent reselection may change the provider behind the recorded explanation. File-only work does not call permission or capture dependencies and stores nil target fields in the existing metadata format.

Typed plans go through typed admission and action-scoped approval. The present executor supports workspace file creation only; unsupported typed actions must be rejected before a task is published, not left in an approval state that cannot advance. A plan alone grants no execution authority. Existing contextual legacy admission remains explicitly transitional and must be removed as provider planners and executors migrate; this slice does not complete M1.

## Queue and verification

Preserve workspace ownership, cancellation, metadata rollback, and the v5 journal. Planning errors must not start delegated execution. Cancellation or metadata failure must leave no newly runnable orphan task; persistence failures must remain visible rather than being swallowed.

Use the real queue, inventory inspector, and selector in the regression test. Inject the inventory loader and OS boundaries, never a preselected runtime. Prove that a canonical file request queues an approval-held typed plan without permission or capture calls, then approves, creates the expected file, and records history. Cover malformed input, incorrect result identity, exact workspace mismatch, legacy-only and typed-only providers, context retry on the same provider, latency updates, and cancellation before publication.

The capability candidate contributes its no-capture queue order, nil target metadata, and explicit rejection behavior. Reject its extra planning-requirement enum, copied capability projections, and two independent selector calls. Reject the result candidate's implicit compatibility adapter and context-driven reselection; the explicit legacy protocol and fixed provider above replace them. No generic legacy-to-typed conversion is permitted.
