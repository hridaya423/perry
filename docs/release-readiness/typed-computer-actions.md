# Typed computer actions

Owner: App/Execution. Scope: the M1 computer-action execution boundary. Evidence comes from an unsigned Apple Silicon Debug build and a controlled JSON-RPC driver fixture, not live application control.

AccessibilityActionRuntime parses a legacy Step into ComputerAction before calling Cua. The compatibility CuaDriverClient.execute(Step, sessionID:) entry point performs the same parse before starting a driver or refreshing a target. Cua's executor and target-resolution helpers consume typed operations, coordinates, and selectors rather than reading the planner's string dictionary.

The parser rejects nonfinite or incomplete coordinates and accepts only explicit windowPixels coordinates. Scroll amounts, directions, granularity, drag duration, and interpolation counts follow the pinned Cua 0.22.1 binary's describe schemas. Keyboard aliases are normalized before dispatch. Key presses and hotkeys preserve supplied element targets. Text retains its leading whitespace and newlines.

The focused CuaDriverClientTests suite passed 25 tests with zero failures in /tmp/perry-typed-computer-tests.log on August 31, 2026. Four added contract tests cover malformed input before process startup, all eight action variants on the wire, keyboard element targeting, and default scroll amounts only when the field is absent. The wire assertions check the process, window, session, and background-delivery fields. Existing connection-generation, target-retirement, signing, and verification tests also passed.

A fifth regression reproduced an unsafe fallback: a missing element identifier on a key press dispatched the key without an element target. Both the expected rejection and the no-dispatch assertion failed in /tmp/perry-typed-target-before.log. The resolver now throws when a supplied identifier cannot resolve, rather than returning an absent target. After this correction, the full unsigned Debug app suite passed 239 tests, skipped two live Cua tests, and had zero failures in /tmp/perry-typed-computer-final.log. Independent code review remains pending; these runs used the development checkout.

This does not complete M1: planners and task persistence still use the legacy Step payload, verification still reads that payload, and workspace and integration operations need their own typed migrations. Live target-app behavior, latency budgets, protected-surface coverage, and clean-checkout reproduction remain separate release gates. No evidence status is promoted by this change.

The independent parser review identified blank optional targets and empty punctuation-delimited key components. Both now reject before driver startup; spaced combinations remain accepted. The reviewer confirmed the parser corrections. The same review found that the BYOK JSON decoder omitted key modifiers. It now preserves string and array modifiers, rejects malformed supplied selectors/modifiers/integer fields, and preserves integer-valued action parameters without adding a decimal suffix. A planner-to-Cua test also reproduced and corrected a Foundation Boolean-bridging error that discarded a numeric coordinate of 1. That intermediate failed run is /tmp/perry-cua-cancel-reviewed-app.log.

Final evidence: 242 app tests passed, two live Cua tests skipped, zero failures in /tmp/perry-cua-request-final-app.log; 13 BYOK parser tests passed in /tmp/perry-byok-selector-tests.log. The app test exercises actual planner JSON decoding, AccessibilityActionRuntime, and the controlled Cua wire fixture together. Independent source review of the final BYOK decoder corrections found no blocking issue on August 31, 2026. That review covered selector validation, modifier preservation, integer serialization, and the associated tests; it did not rerun builds or re-audit request cancellation or the rest of the app.
