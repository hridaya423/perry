# Execution / agency layer: review findings

## Shape
Perry has no single Run concept. Seven features (foreground Do, background queue, Guide, routine replay, scheduled Perrys, suggestions, undo) each re-implement start → gate → drain events → mirror state → finalize → cancel/pause/steer. Three state machines (`SupervisorStateMachine` in PerryCore, `ExecutionLifecycle` in SessionController, `TaskLifecycleState` in TaskCoordinator), five outcome enums (`DoOutcome`, `AgentFinish`, `TranscriptEntry.Outcome`, `ReportOutcome`, `Turn.Outcome`), four converters between them. Only two things are genuinely different: the model-driven loop (`AgentLoop` via `AgentCoordinator`) and typed-plan replay (`DoSupervisor`, used only by routines). Target: one `RunKind` enum, one `RunHandle { pause, resume, steer, stop }` both runtimes conform to, one `runToEnd(kind) -> RunResult` drain, one finalizer.
