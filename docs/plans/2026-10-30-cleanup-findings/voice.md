# Voice / speech stack: review findings

## Shape
One real pipeline: hold a key → capture mic → transcript (on-device or realtime) → route → speak reply → user can interrupt. The code has seven. `DictationController` is constructed in 6 places (verified: VoiceController, SFSpeechInput, TalkSession default + AppSubsystems click factory, GuideVoiceCommands, InterviewListener). `WakeWordListener`, `NeuralSpeechPlayer` (Voice/NeuralSpeech.swift), `MicrophoneLevelMeter`, `DictationController` and `RealtimeVoiceSession` each build their own `AVAudioEngine` (verified 4 files). Two classes re-implement a CGEventTap + NSEvent fallback (verified). Target: one `MicSession` (engine, tap, device choice, route recovery) feeding a `Transcriber` (SFSpeech / SpeechAnalyzer / Realtime), one `SpeechOut` (system / Kokoro / realtime) with one interrupt call.

IMPORTANT constraint (recent crash fix, keep it): every `installTap` must go through `DictationController.installTap` (or its successor), which catches the Objective-C exception via `App/ObjCException.m`; a fresh AVAudioEngine per dictation start. See progress.md "crash root cause (2026-10-29)". Keep test `testATapAVAudioEngineRefusesComesBackAsFalseInsteadOfAnException` passing. Also keep: natural voices only (no compact macOS voice — `testNoNaturalVoiceMeansSilentNotCompact`), Kokoro legacy route on macOS 27, failed neural sentence falls back to system voice.
