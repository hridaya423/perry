# Model providers + integrations: review findings

## Shape
One `ModelProvider` protocol and one `ModelRequest`/`ModelEvent` model exist and are sound (`ModelTypes.swift:75-181`). Missing: a wire-format seam beneath them. Four HTTP providers re-implement init, warm, stream, SSE loop, termination checks. Four decorators re-forward the whole provider surface. Two OAuth stacks with separate PKCE/token/refresh. Two integration systems (curated REST in `RemoteIntegrations` + MCP connectors). `App/RemoteIntegrations.swift` (2230 lines) mixes catalog data, policy, a GraphQL lexer, credentials, OAuth and an HTTP client.

## Findings
1. [MAJOR] Four HTTP providers copy one skeleton: `Packages/PerryBrain/Sources/PerryBrain/Providers/{Anthropic,OpenAIResponses,OpenAIChatCompatible,Gemini}*.swift`. Same init (baseURL, apiKeyProvider, models, transport), warm(), stream(), run(), `for try await line … parser.feed`, "ended before the model confirmed completion". Only request building, content mapping, event handling differ. Move: `protocol WireFormat { func request(_:) throws -> URLRequest; mutating func consume(_ event: SSEEvent) throws -> [ModelEvent] }` + one generic `HTTPModelProvider<Wire>`. Also: tool-result text join appears 3 times; Anthropic duplicates image-part mapping in one function (AnthropicMessagesProvider.swift:140-195); `ProviderPreset.makeProvider` and `modelsRequest` switch on wire format twice.
2. [MAJOR] Two OAuth stacks / two PKCE: `App/RemoteIntegrations.swift:1315-1330, 1331-1650, 2063-2230` vs `MCP/MCPAuthorization.swift:114-300`, `MCP/MCPOAuthSession.swift:62-124`. Both build verifier, S256 challenge, state, form-encoded token POST, refresh. `OAuthToken`/`StoredOAuthCredential` vs `MCPOAuthCredential` parallel credential types. `OAuthCoordinator` already takes `MCPAuthorizationUserAgent`. Move: one OAuth client (PKCE, token POST, refresh, revoke) in PerryBrain; REST definitions and MCP discovery both feed it endpoints. Keep device flow as a second method if used.
3. [MAJOR] GraphQL lexer guards requests Perry composes itself: `RemoteIntegrations.swift:610-885` (`allowsRemoteRequest`, `graphQLTokens`, `graphQLOperation`, ~190 lines). Verified by integrator: the only read path is `App/Tools/IntegrationBackendAdapter.swift` → `client.preview(definition:action:)` with fixed `quickActions`; the only free text is the Notion search query, which the adapter splices into a JSON body by string concatenation (`#"{"query":""# + Self.jsonEscaped(query) + …`) under `if definition.id == "notion", action.id == "search"`. Writes come from five typed `RemoteIntegrationWriteParameters`. Move: delete the tokenizer; mark read/write by construction on the quick action / write operation; build bodies with JSONEncoder/JSONSerialization; make the Notion search parameter a property of the quick action, not a string special case. Keep a path-prefix allow-list only if it still guards something real.
4. [MAJOR] `RemoteIntegrationDefinition` uses ~12 `switch id { case "notion": … }` blocks (`:277-610`: testPath, testMethod, testBody, connectionHint, defaultHeaders, allowedReadPathPrefixes, allowedWritePathPrefixes, allowedWriteOperations, quickActions, allowsReadOnlyPost, authorizationScopeParameter, authorizationScopeSeparator, private Provider enum mapping three Google ids). The catalog (`:913-1027`) is already a table — move these into catalog fields. `CredentialReference(service:"dev.perry.integrations", account:"integration.\(id)")` hand-typed per entry → derive it.
