# UI surfaces: review findings

## Shape
One presentation model already exists: `NotchPresentation` (a priority stack of AnyView entries) rendered by `CompactConversationView` inside the single `SessionPanelPresenter` panel. Most surfaces (intent card, dialog, confirmation, task question, guide controls, routine, strip, failure) go through it. So delete what's built around it rather than adding a model: five `*Window` classes that aren't windows, four hand-written copies of the async-continuation presenter, an AppKit status capsule duplicating the notch, five hand-configured NSPanels, a second theme in the overlay package, and an unused slice of PerryTheme.

Owner preference to respect: hand-drawn ink art stays in onboarding; product rows use real app icons. Do not change visuals; this is structure only.

IntentCardWindow keeps `static var active` while IntentCardPresenter keeps `window` (current card tracked twice). 2. [MAJOR] `*Window` classes that forward present/remove: `GuideControlsWindow.swift:171-203`, `RoutineReviewWindow.swift:190-218`, `RoutineOffer.swift:62-77`, `AgentActivityStrip.swift:566-608`. Remove `AnyView(EmptyView())` placeholders (IntentCardWindow:14, AgentActivityStrip:572).
3. [MAJOR] `NotchStatusController.swift:1-240` hand-builds 11 AppKit subviews + 3 separators for a capsule (recording/tasks/reviews/wake). Move: a small SwiftUI view with `sizingOptions = []`. RISK: this changes rendering; the integrator will render-check. If you are not confident, leave it and say so.
