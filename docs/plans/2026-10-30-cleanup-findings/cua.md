# Computer use / Cua / agent tools: review findings

## Shape
Target: one typed seam, `DriverSession.perform(Action) -> Outcome`, over one MCP stdio client with Codable payloads. Today: a hand-rolled JSON-RPC client inside the 1758-line `CuaDriverClient` actor, a pass-through handle, a service, three parallel copies of the action vocabulary, `[String: Any]` everywhere. PerryBrain already ships `JSONRPCConnection` (229 lines) and `MCPConnector` with an NDJSON stdio Process transport (`Packages/PerryBrain/Sources/PerryBrain/MCP/MCPConnector.swift:358-379`, verified). A click crosses ~12 hops: UIActionExecutor.run → resolveTarget/ResolvedTarget → windowPixels → ComputerAction.Operation → withCuaWorker (+explained error mapping) → CuaWorkerHandle → CuaWorkerService.execute → CuaDriverClient.execute → refreshSessionTarget → performAction/actionArguments/resolveElementToken → callTool/invokeTool → sendRequest. Only the executors, the worker service (admission, leases, retirement) and the process client earn their place.

## Findings
1. [BLOCKER] Third hand-rolled JSON-RPC/MCP stdio client. `App/CuaDriverClient.swift:392-453, 891-1015, 1358-1609`: own pending table, readBuffers, newline framing, timeout tasks, initialize handshake; `receive(line:)` parses JSON, re-serializes `result`, `structuredValue` parses again (3 parses per reply). Move: reuse PerryBrain's JSON-RPC/MCP stdio transport (App already imports PerryBrain); keep only the process-group reaper (`CuaOwnedProcess`, ~60 lines) and the timeout/wedge behaviour the app depends on. Check MCPConnector's process handling covers what the Cua client needs (signing verification of the binary, process group kill, restart); if it doesn't, extend the shared one minimally rather than keeping two. Keep valid external-constraint notes (pid/group reaping, wedge timeout).
2. [MAJOR] `execute` (612-744) and `stepRequest` (1200-1246) are the same switch twice: every case builds (toolName, args) for direct call and for run_steps; each result message hand-written. Move: one `request(for: Operation) -> (tool, args)`; one message table.
3. [MAJOR] Dead package code (verified 0 refs outside package): `Packages/PerryCapture/Sources/PerryCapture/PerryScreenshot.swift`, `PerryVisionOCR.swift`, `PerryCaptureError.swift` (PerryScreenCapture, PerryTextObservation, PerryVisionTextRecognizer, PerryTextTargetMatcher, PerryTextMatch, PerryCaptureError). Only `PerryPermissionProbe` is used. Delete them and `CaptureFoundationTests` (91 lines). If PerryCapture is left with one file, fold PerryPermissionProbe into PerryCore (or wherever its callers want it) and delete the PerryCapture package, updating project.yml and any Package.swift dependency lists.
4. [MAJOR] `App/Tools/UITools.swift:22-35, 294-763`: ten executors with the same boilerplate; each carries `workers, lease, observations, onActuation, locate`; `tier: .yellow, surfaces: [.agent], requiredCapabilities: [.tools, .vision]` per spec; `bringForward → withCuaWorker → showActuation → verifiedResult` per run. Move: one context struct + a table of (name, schema, makeOperation); keep pointer-glide paths as the one real branch. (Note: the `lease` field repeated across ~14 tool structs including ScreenTools — a `ToolContext.withWorker` would do. `App/Tools/ForegroundWorkerLease.swift` is owned by the execution agent; only change its call sites.)

OWNER DECISION — read tools. `CuaDriverClient.swift:1653` hard-codes `let value: String? = nil` (commit 30994ea "Separate Guide completion claims from evidence and discard unsafe field values" — a privacy change). Consequence: `App/Tools/DocumentTools.swift:57` (`document.read`) only works via the PDF fallback and `App/Tools/BrowserTools.swift:89-92` (`browser.read`) never returns a URL. Decide by reading: if restoring values for non-secure elements (sensitivity != .secure; never values of AXSecureTextField) makes these tools do something no other tool does, restore it that way and make sure the Guide path that motivated 30994ea still doesn't treat field values as completion evidence. If another tool already gives the same information, delete the dead paths instead. Report which you chose and why.
